# Status update sintetico

One self-contained HTML page that answers, per stream, three questions in a few seconds: how far each activity is, when it will finish, and whether it makes the date. Under each chart, only the blockers that stop an activity of that chart. Nothing else: no narrative, no history, no action list.

The template is [assets/template.html](assets/template.html): fixed CSS and rendering code, placeholder data between `DATI` and `FINE DATI`. The page computes percentages, ETAs, lights and totals itself from the data block, with the rules in section 3.

## 1. Before writing

- State the target path and get the user's confirmation. A new update is a new dated file, never an overwrite of the previous one.
- Read the sources first: trackers, dashboards, test status, chat recaps, tickets. Every number on the page comes from a source with a date. No numbers from memory.
- **Data date per stream.** Each stream carries the date of its own data. When a stream's data is older than two working days, ask the user for fresh data before building; if they say to go ahead, the old date stays visible on the stream.
- **Target date per stream.** Ask for it when the sources do not state it. It is the date the activities must be complete by (for a cutover, usually the day before it), not the cutover itself.
- Ask only what changes the result: missing target, stale data, an activity whose scope is unclear. For anything else use a sensible default and say which one.

## 2. Content rules

- **Activities.** One row per activity in the order of the source (asset list, test lines), the same order every time so readers can compare days. 3 to 12 rows per stream; above that, group.
- **Progress is counted, not estimated.** `done` and `total` are counts from the source (pods, Apigee artefacts, tests). The page shows `done/total` and the percentage on every row, and a `Totale overall` row summing only the rows that have numbers.
- **No numbers means grey.** An activity the source does not quantify gets `done: null, total: null`: grey, `n.d.`, out of the total, never green.
- **Partial scope.** When the source names a component without numbers (for example Apigee cited with no count), set `missing` to its name: the row cannot be green until it is reported.
- **Blockers.** Only what stops an activity in the chart: one line each with what is blocked, the activities it stops, who resolves it, the ticket or `ticket da fornire`, and the expected resolution date or `data non indicata`. A risk that stops nothing today is not a blocker and stays off the page.
- **No attribution by inference.** An owner or a date the source does not state is written as not stated, never guessed.
- Terse. Activity names 1 to 3 words. Blocker text at most 12 words. The reason next to a light is generated by the page; do not add prose around it.
- The user's language. The template's interface strings are Italian; translate them when the user writes in another language.
- No em dash and no double hyphen as punctuation. No emoji.

## 3. Lights and ETA

The lights mean one thing each, the same on every stream:

| Light | Meaning |
|---|---|
| Green, `In linea` | The activity makes its target date and nothing stops it |
| Yellow, `A rischio` | The date is at risk: something could still make it slip |
| Red, `Non traguarda` | The date will not be met on the facts we have |
| Grey, `n.d.` | No numbers in the source |

**ETA**, in this order:

1. Complete (`done` equals `total`, nothing `missing`): `fatto`.
2. A date stated by the owner or the source: `eta` in the data, shown as declared.
3. Two snapshots with the same `total`: pace = progress between them divided by the working days between them (Saturday, Sunday and the `holidays` excluded); ETA = data date plus the remaining work at that pace, rounded up to whole working days.
4. Otherwise `n.d.`: one data point, no progress, or a total that changed. Never extrapolate from a single point.

**Light**, first matching rule wins:

1. Grey when the activity has no numbers.
2. Red when the target has passed and the activity is not complete.
3. Red when an open blocker on the activity has a stated resolution date after the target.
4. Red when the ETA falls more than `margin_days` working days after the target (default 2).
5. Yellow when an open blocker stops the activity (no date, or a date within the target), when part of the scope is `missing`, when the ETA is `n.d.` and the activity is not complete, or when the ETA is after the target by at most `margin_days`.
6. Green otherwise.

Two consequences, on purpose: an activity at 100% with an open blocker is yellow, never green; and a slow activity with no second data point is yellow, not red, because red claims certainty. The stream's light is the worst light among its activities, grey ignored. The page writes the reason beside every non-green light.

## 4. Building

1. Copy `assets/template.html` to the confirmed path.
2. Edit the data block between `DATI` and `FINE DATI` only: `title`, `source` (one line naming the sources and their dates), `today`, `margin_days`, `holidays`, and one object per stream with `name`, `target`, `target_label`, `data_date`, `unit`, `activities` and `blockers`. Each blocker lists the `activities` it stops by name. Leave the CSS and the rendering code alone.
3. Dates are ISO (`2026-11-19`). The page prints them as `gio 19.11`.

## 5. Verification, before calling it done

- Open it at desktop width and at 375 px, in light and in dark mode. At 375 px `document.documentElement.scrollWidth` equals the viewport width, and no row wraps its numbers or its light label.
- No console errors. `window.__check` lists any data problem the page found (a blocker naming an unknown activity, `done` above `total`, a missing target); it must be empty.
- Recompute two rows by hand, one with a pace and one with a blocker, and compare with the page. Recompute the `Totale overall` row.
- Look at the screenshots for text running past a bar or a cell.
- No U+2014 character in the file.
- Show the user the screenshot and the light of each stream with its reason, then call it done.

## 6. After

In a folder with an index, add the row: title, date, one-line summary with the light of each stream. A new update is a new file; the previous one stays as history.
